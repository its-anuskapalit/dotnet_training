1) What is a Page in SQL Server? Diagram

SQL Server stores data on disk in 8 KB pages. Tables and indexes both consist of pages.

Diagram — Page and Extent
Page = 8 KB
+--------------------------------------+
| Rows (or index entries)              |
| Free space                           |
+--------------------------------------+

Extent = 8 pages = 64 KB
[Page1][Page2][Page3][Page4][Page5][Page6][Page7][Page8]
i
Why it matters:
Query performance improves when SQL Server reads fewer pages. Indexes help reduce page reads.

2) What is an Index? Diagram

An index is a structure that helps SQL Server find rows faster, similar to a book index.

Without index (scan)
Need: LastName='Smith'

SQL Server reads many pages:
Page1 -> Page2 -> ... -> PageN
Checks rows one by one
With index (seek)
Index on LastName exists

SQL Server navigates:
Root -> Intermediate -> Leaf
Jumps directly to matching keys
✓
Definition:
An index is a B-Tree structure that speeds up reads but costs extra storage and slows writes.

3) Clustered Index — basics

A clustered index defines the physical order of rows. The leaf level IS the data.

Diagram — Clustered index (leaf = data)
Root
  |
Intermediate
  |
Leaf  ==> DATA PAGES (actual rows)
i
Rule: One table can have only one clustered index.

4) Nonclustered Index — basics

A nonclustered index is separate. Leaf holds index key + pointer to the row.

Diagram — Nonclustered leaf entries
[Key: LastName='Smith'] -> [Pointer to row]

Pointer is:
- Clustered key (if clustered table)
- RID (if heap table)

5) Create Clustered Index (sample)

We create a practice table copy so we can safely create/drop indexes.

Create practice table + clustered index
USE AdventureWorks2019;
GO

DROP TABLE IF EXISTS dbo.Product_Practice;
SELECT TOP (5000)
  ProductID, Name, ProductNumber, Color, ListPrice, ModifiedDate
INTO dbo.Product_Practice
FROM Production.Product
ORDER BY ProductID;

-- Create Clustered Index
CREATE CLUSTERED INDEX CX_Product_Practice_ProductID
ON dbo.Product_Practice(ProductID);

-- Verify indexes
SELECT i.index_id, i.name, i.type_desc
FROM sys.indexes i
WHERE i.object_id = OBJECT_ID('dbo.Product_Practice');

6) Create Nonclustered Index (single key)

Create nonclustered index on ProductNumber
USE AdventureWorks2019;
GO

CREATE NONCLUSTERED INDEX IX_Product_Practice_ProductNumber

SELECT i.index_id, i.name, i.type_desc

7) Single key vs Composite (multiple keys)

A composite index has multiple key columns. Column order matters (left-most rule).

Diagram — Left-most prefix rule
Index on (Color, ListPrice)

Good:
WHERE Color='Black'
WHERE Color='Black' AND ListPrice>=1000

Not great:
WHERE ListPrice>=1000  -- Color missing
Create composite index: (Color, ListPrice)
USE AdventureWorks2019;
GO

CREATE NONCLUSTERED INDEX IX_Product_Practice_Color_ListPrice
ON dbo.Product_Practice(Color, ListPrice);

SELECT ProductID, Name, Color, ListPrice
FROM dbo.Product_Practice
WHERE Color = 'Black' AND ListPrice >= 1000
ORDER BY ListPrice DESC;

8) INCLUDE (covering index)

INCLUDE adds extra columns to the leaf so SQL Server can return them without extra lookups.

Create covering index: ProductNumber INCLUDE Name, ListPrice
USE AdventureWorks2019;
GO

DROP INDEX IF EXISTS IX_Product_Practice_ProductNumber ON dbo.Product_Practice;

CREATE NONCLUSTERED INDEX IX_Product_Practice_ProductNumber_Cover
ON dbo.Product_Practice(ProductNumber)
INCLUDE (Name, ListPrice);

9) How to see Index Keys and Included Columns Must Know

Freshers usually ask: “I created an index, how do I see the key columns and INCLUDED columns?”

i
Meaning:
  • Index key columns = columns that form the sorted order of the index (used for seek).
  • Included columns = extra columns stored only in leaf level (used to cover a query).
  1. In SSMS, expand: Databases → AdventureWorks… → Tables
  2. Find your table: dbo.Product_Practice
  3. Expand: Indexes
  4. Right click an index (example: IX_Product_Practice_ProductNumber_Cover) → Properties
  5. Go to:
    • General → columns list (shows key columns and order)
    • Included Columns → shows included columns
✓
Quick visual check:
Keys are shown in the main columns list; Included columns appear in a separate section.

This query shows: index name, key columns (with order), and included columns.

USE AdventureWorks2019;
GO

DECLARE @TableName SYSNAME = 'dbo.Product_Practice';

;WITH idx AS (
  SELECT
    i.object_id, i.index_id, i.name AS index_name, i.type_desc, i.is_unique
  FROM sys.indexes i
  WHERE i.object_id = OBJECT_ID(@TableName)
    AND i.index_id > 0
)
SELECT
  idx.index_name,
  idx.type_desc,
  idx.is_unique,
  CASE WHEN ic.is_included_column = 0 THEN 'KEY' ELSE 'INCLUDE' END AS column_role,
  ic.key_ordinal,
  c.name AS column_name,
  ic.is_included_column
FROM idx
JOIN sys.index_columns ic
  ON ic.object_id = idx.object_id
 AND ic.index_id = idx.index_id
JOIN sys.columns c
  ON c.object_id = ic.object_id
 AND c.column_id = ic.column_id
ORDER BY idx.index_name,
         CASE WHEN ic.is_included_column = 0 THEN 0 ELSE 1 END,
         ic.key_ordinal,
         c.name;
i
How to read output:
Rows with column_role=KEY show key columns (in order using key_ordinal). INCLUDE rows show included columns.
USE AdventureWorks2019;
GO
EXEC sp_helpindex 'dbo.Product_Practice';
!
Limitation:
sp_helpindex may not clearly separate INCLUDE columns in all cases. Use Option B for full details.

10) How to see Index “Values” (real index entries) Advanced

Strictly speaking, SQL Server does not give a simple “SELECT * FROM index” view, because an index is stored as pages and B-Tree nodes.

But for learning, you can see the index entries by running a query that uses the index and selecting the key columns (and included columns).

✓
Practical meaning of “Index Values”:
Index values = values of the key columns stored in sorted order in the index (plus included columns at leaf).
Example: See the sorted index key values
USE AdventureWorks2019;
GO

-- If you created: IX_Product_Practice_ProductNumber_Cover
-- key = ProductNumber, include = Name, ListPrice

-- This shows the "index values" (key values in sorted order)
SELECT TOP 50
  ProductNumber,   -- index key column
  Name,            -- included column (stored at leaf)
  ListPrice        -- included column
FROM dbo.Product_Practice
ORDER BY ProductNumber;  -- aligns with index key order
  1. Turn on Actual Execution Plan (Ctrl + M).
  2. Run the query above.
  3. In the plan, click the operator and see the index name used (seek/scan).
-- Optional: Force index usage ONLY for learning (not a production recommendation)
SELECT TOP 50 ProductNumber, Name, ListPrice
FROM dbo.Product_Practice WITH (INDEX(IX_Product_Practice_ProductNumber_Cover))
ORDER BY ProductNumber;
!
Warning:
Index hints can make performance worse in real systems. Use them only to learn what is happening.
i
Deep-dive (optional):
There are diagnostic commands (like DMVs and page inspection) to view internals, but freshers should focus on keys, includes, and plans first.

11) Performance: Without index vs With index

Proof = fewer reads + better plan.

What to checkHowGood
Logical readsSET STATISTICS IO ON;Reads drop
Execution planCtrl + MScan → Seek
CPU/TimeSET STATISTICS TIME ON;Lower CPU/time

Demo 1 — Heap scan → Nonclustered seek

Run full demo script
USE AdventureWorks2019;
GO

-- Create HEAP table
DROP TABLE IF EXISTS dbo.Person_Practice;
SELECT TOP (20000)
  BusinessEntityID, FirstName, LastName, ModifiedDate
INTO dbo.Person_Practice
FROM Person.Person
ORDER BY BusinessEntityID;

-- Without index
SET STATISTICS IO ON;
SET STATISTICS TIME ON;

SELECT TOP 200 BusinessEntityID, FirstName, LastName
FROM dbo.Person_Practice
WHERE LastName = 'Smith'
ORDER BY FirstName;

-- With index
CREATE NONCLUSTERED INDEX IX_Person_Practice_LastName
ON dbo.Person_Practice(LastName);

SELECT TOP 200 BusinessEntityID, FirstName, LastName
FROM dbo.Person_Practice
WHERE LastName = 'Smith'
ORDER BY FirstName;

SET STATISTICS IO OFF;
SET STATISTICS TIME OFF;

Demo 2 — Composite + INCLUDE

Run composite + INCLUDE demo
USE AdventureWorks2019;
GO

DROP TABLE IF EXISTS dbo.SalesOrderHeader_Practice;
SELECT TOP (200000)
  SalesOrderID, CustomerID, OrderDate, TotalDue
INTO dbo.SalesOrderHeader_Practice
FROM Sales.SalesOrderHeader
ORDER BY SalesOrderID;

SET STATISTICS IO ON;
SET STATISTICS TIME ON;

-- Before index
SELECT TOP 200 SalesOrderID, CustomerID, OrderDate, TotalDue
FROM dbo.SalesOrderHeader_Practice
WHERE CustomerID = 11000
  AND OrderDate >= '2013-01-01' AND OrderDate < '2014-01-01'
ORDER BY OrderDate;

-- Create composite + covering index
CREATE NONCLUSTERED INDEX IX_SOH_Practice_Customer_OrderDate_Cover
ON dbo.SalesOrderHeader_Practice(CustomerID, OrderDate)
INCLUDE (TotalDue);

-- After index
SELECT TOP 200 SalesOrderID, CustomerID, OrderDate, TotalDue
FROM dbo.SalesOrderHeader_Practice
WHERE CustomerID = 11000
  AND OrderDate >= '2013-01-01' AND OrderDate < '2014-01-01'
ORDER BY OrderDate;

SET STATISTICS IO OFF;
SET STATISTICS TIME OFF;

Seek vs Scan (quick)

Seek
Reads only matching entries/pages.
Usually faster for selective filters.
Scan
Reads many entries/pages.
Sometimes cheaper if query returns most rows.

SARGable WHERE

Bad

WHERE YEAR(OrderDate)=2013

Good

WHERE OrderDate>='2013-01-01'
  AND OrderDate<'2014-01-01'
